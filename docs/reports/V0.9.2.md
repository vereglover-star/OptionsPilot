# V0.9.2 — Complete the service extraction: engineering notes

Per-commit engineering notes, written as each commit lands. The narrative
summary lives in `CHANGELOG.md`; the commit table with hashes lives in
`ROADMAP.md` ▸ V0.9.2 ▸ Commit map. This file is the *why it was done that way*
and, more usefully, the *what went wrong on the way*.

Standing rules this milestone worked under: characterization tests are written
**before** the code they characterize; `tests/test_ui_server.py` must pass
**unchanged** through C2–C5, because editing it destroys the evidence that a
move changed nothing; and every new gate is demonstrated **failing** as well as
passing, with the file restored byte-identically afterwards (`cp`/`cmp`, never
`git checkout`).

---

## C1 — the service error hierarchy (`cefe4da`)

`core/errors.py` (one class, imports only `__future__`) and `services/errors.py`
(`ServiceError` plus exactly one subclass per member of `ERROR_CODES`). Nothing
raises them yet; that is C7, and the separation keeps both reviewable.

The defect being addressed is H-7: `ui/api_v1.py` infers a status from the
*builtin* type — `ValueError` becomes 422 and `KeyError` becomes 404 — but
`ValueError` is what `int("x")` and half the standard library raise. An internal
defect reached the user as a client mistake, and the traceback that would have
found it was discarded because the handler thought it understood the failure.

**Decision worth defending.** The code is validated in `__init_subclass__`, at
**import** time, rather than when the error is raised. An error class's failing
path is by definition a moment already going badly; import is the only time this
can fail cheaply.

**What went wrong.** A test searched the source *text* for `"404"`/`"422"` and
failed on my own docstring, which explains the transport behaviour it replaces.
Rewritten as an AST scan for integer literals in the HTTP range. Third time in
this project's recent history that a text-matching test broke on prose
explaining the rule it enforces.

## C2 — `ChartService` (`74de6b2`)

`ui/server.py::candles_payload` (126 lines) moved to `services/charts.py`. The
server method became a three-line delegation; `ui/server.py` lost 122 lines and
stopped importing `analysis` entirely.

**The golden caught a real defect within one run.** The extracted service read
its own module-level `utcnow`, so the UI suite's frozen clock no longer reached
it and nine market-data tests began reporting `empty` windows. In production
this is subtler than a test failure: the chart would request a window around the
wall clock while the rest of the app worked from the host's. The clock is now an
injected collaborator, like the provider.

**The generalizable lesson for C3–C5.** "Move the code" reads as safe because
the body is identical; what actually moves is *which module's globals the body
resolves*. Every `utcnow`, every module constant, every `self.cfg`
reach-through is a binding that changes owner.

**Architecture.** The allow-list was widened by two, deliberately (that file's
own docstring sanctions this "with justification, never to green a test").
`analysis` — because the endpoint's whole claim is parity with the library the
engine trades with, and injecting it would let two callers supply different
ones. `data` — bounded by a new, *narrower* assertion permitting only
`data.base` and `data.sessions`. Net: the layering statement is stronger than
before, not weaker.

**Not done, deliberately.** `orchestrator.WINDOW_DAYS` was not moved to `core`.
Its comment claims the orchestrator as "its natural owner", and reversing a
documented prior decision is a bigger change than passing the table down.

## C3 — `MarketDataAdminService` (`4269cfe`)

Diagnostics, the text report, trace replay and the twelve Settings ▸ Market data
control calls.

**Named against the specification, on purpose.** The spec says extract
`MarketDataService`; `data/service.py::MarketDataService` — the tier ladder —
has owned that name since V0.5.2. Two identically-named classes in one codebase
is a permanent tax on every import line and every search.

**The twelve delegations were the actual risk.** Each was two lines differing
only in which `MarketDataControl` method it named, so a copy-paste naming the
wrong one is easy to write and invisible to review: a settings page that resets
the provider order when asked to test a connection, with a green suite behind
it. They now route through one `_delegate(name, *args)` dispatcher and are
pinned by a parametrised table asserting method *and* arguments, plus a test
that the table is **complete**.

**The import/inject rule this commit established**, followed by C5:
`data/report.py` is *imported* because it is pure stdlib and is the ONE
diagnostics renderer, so a second must not be substitutable; `data/replay.py` is
*injected* because it reaches the registry, the adapters and the quality checks.

**What went wrong — and this is the important one.** The chart gate failed, so I
stashed, tested the previous commit, saw green, and stated *"C3 caused it"*.
That was wrong. The runs were sequential against a **live** provider — no
control, no interleaving, n=1 per arm. The check subsequently passed twice at
the C3 state. On a network-dependent gate the correct first move is to re-run
the *same* state, which is what actually resolved it. I stated a causal
conclusion the evidence did not support, and it would have sent an hour into
rewriting a correct commit.

## C4 — `TradingService` (`388384e`)

The manual order path, the option chain, account metrics and the whole scan
cycle. The highest-consequence extraction: C2 and C3 legitimately took no lock;
here it is real.

**The lock scope is asserted, not reviewed.** `threading.RLock` exposes
`_is_owned()`, so an instrumented collaborator records whether the lock was held
at the instant the real code reached it.

| Path | Inside the lock | Outside |
|---|---|---|
| `place_order` | chain lookup, quote, risk approval, `orders.place` | `order.to_dict()` |
| `run_cycle` | `run_cycle`, equity/summary bookkeeping | `fetch_watchlist_candles` |

`order.to_dict()` being outside was **one line of indentation from being lost
and nothing had ever checked it**.

**Two locks stay two objects.** The injected `RLock` guards orchestrator state;
`cycle_lock` (a plain `Lock`, owned by the service) serialises whole cycles.
Making the service build its own orchestrator lock was demonstrated and it
collapses the entire scope assertion — `orders.place` then reports running
*unlocked*.

**A new architecture guard, and the one that matters most in this repository.**
`services` may now import `broker`, bounded to `broker.base` and
`broker.orders` — the order *vocabulary*. `broker/registry.py`, which holds the
Alpaca/Tradier/Webull/IBKR stubs, is permanently excluded: this is a
paper-trading-only system by design, and a reusable application layer that
cannot import the registry is one in which no future host can construct a live
adapter by accident.

**On scope.** The tempting narrowing was to leave the scan cycle behind, with a
defensible-sounding reason (V0.9.1 owns background work). Measuring first — 20
read sites, all local, all mechanical — showed that reason was rationalisation.
The cycle moved; runtime *ownership* stayed exactly where V0.9.1 put it, because
task registration and the task bodies never left `ui/server.py`.

**What went wrong.** A test I wrote banned *all* lock construction in the module,
which is simply wrong — `cycle_lock` legitimately belongs there. And ruff caught
a stray `f` prefix I introduced *after* my own lint run: run the gate after the
last edit, not after the last edit you happened to think was risky.

## C5 — `BacktestService` (`ddafce3`)

The single job slot: the atomic claim, the parameter hand-off, the candle
windows, the report writing and the `backtest_job` record. Task *registration*
stays in `ui/server.py`.

**Reading the consumer test before designing is what went right.** Grepping
`tests/test_runtime_lifecycle.py` first showed it monkeypatches
`server._run_backtest` to block a worker deterministically. That produced the
drain-then-call-the-seam shape. Designed the obvious way, I would have
discovered the constraint *after* writing the service, and the tempting fix
would have been editing the test — destroying the evidence.

**What went wrong — a test that was wrong three times.** Moving the parameter
stash out of the claim's critical section is a real concurrency defect, and the
behavioural test could not see it (single-threaded, the parameters still
arrive). The structural replacement then passed against broken code **twice**:
first it unioned the assignments of every `with self._lock` in `start()`, then
it accepted *any* single block. Both were satisfied by the failure-release
branch, which legitimately assigns `self._pending = None` and `self.job`
together. Only the **first** critical section answers the question.

I caught it only because the induced-failure demo *did not fire*. Had I trusted
the green test I would have shipped a guard asserting nothing, and written a
confident report saying otherwise. **The induced-failure step is not ceremony —
it is the only thing that tests the test.**

## C6 — the guide moves into the service layer

`optionspilot/ui/guide.py` moved to `optionspilot/services/guide.py` via
`git mv`, so the history follows.

The guide was always a pure domain layer that happened to sit in the transport
package: it imports nothing but `re` and `dataclasses`, and all 43 assertions in
`tests/test_guide.py` passed across the move with **only the import path
changed**. That file is the characterization — writing a new one would have been
theatre.

**No compatibility shim**, per the standing preference for deleting over
wrapping. Two import paths for one module means the stale one is the one a
future reader copies, so a test asserts `optionspilot.ui.guide` raises
`ModuleNotFoundError`. A second test pins the module's purity on the AST
(`__future__`, `re`, `dataclasses` and nothing else) — it is now the purest
module in `services/`, and that is worth keeping.

Stale path references were corrected in `CLAUDE.md` (the protected-files list
named the old path), five current-state docs, and five source/test comments that
pointed at the module as a live reference. `CHANGELOG.md` and
`PROJECT_STATE.md` keep their historical wording — those entries describe where
the file *was* when they were written.

## C7 — services state why they refused

Finding H-7 applied at the source. `TradingService` and `ChartService` raise
`ServiceError` subclasses instead of builtins: an unknown contract, a risk veto,
an `OrderManager` refusal and an unparseable timeframe are all
`ValidationError`, each carrying a code and structured `details`.

**The sequencing decision.** This commit changes **no HTTP status**, on purpose.
C7 changes what services raise; C8 changes what the transport does with it.
Splitting them keeps C7 a pure type change whose diff can be read for
correctness, and it is why `tests/test_ui_server.py` and `tests/test_api_v1.py`
both pass unchanged — the `/api/orders` route simply gained `ServiceError` in
its existing `except` tuple, mapped to the 422 the builtins already produced.
Had the two been done together, a reviewer could not tell a deliberate status
change from an accidental one.

**`ValidationError`, not `NotFound`, for a missing contract.** The endpoint
exists and the request was understood; the payload names a contract that cannot
be traded. `NotFound` is for addressing a resource that is absent, which a POST
to `/api/orders` is not doing. Getting this wrong would have turned a legitimate
422 into a 404 — the same class of confidently-wrong status H-7 is about.

**What C7 deliberately did NOT convert.** `services/marketdata.py`'s diagnostics
return `{"error": ...}` dictionaries rather than raising. That is not H-7's
defect: H-7 is about *exceptions* being misclassified by type at the transport.
A diagnostic that returns a structured result is a legitimate design, and a
diagnostic that raises is a worse one — the whole point of the page is to work
when things are broken.

**The guard, and its allow-list.** An AST test fails any `raise` of a bare
builtin under `services/`. Four modules are exempt and **every entry is a
reason, not an exemption**: `runtime.py` (a `TaskSpec` with an unknown lane is a
wiring bug caught at registration), `errors.py` (the hierarchy's own
`__init_subclass__` guard), `idempotency.py` (a closed store is an internal
invariant), `contracts.py` (unconfigured device-token auth is a deployment
fact). All four raise at construction or on an internal invariant, never on the
request path — classifying them would dress a programmer error as a client one,
which is H-7 pointing the other way.

A second test fails if the allow-list names a module that no longer exists. A
stale exemption silently un-guards whatever replaced it, which is the same
failure shape as a catalogue that drifts in one direction only.

**A note on a test that enshrines the defect.** `tests/test_ui_server.py`
asserts that `/api/candles?tf=7m` returns **502 "unavailable"** — a client's
unparseable timeframe reported as an upstream failure. That is the mirror image
of H-7 and it is now a `ValidationError` at the service. The status stays 502
until C8, where the mapping change and the test update belong together.

## C8 — one place turns a failure into a status

New `optionspilot/ui/errors.py` holds `STATUS_FOR_CODE`: one status per declared
error code, total in **both** directions and asserted so. Finding H-7 is closed
by this commit.

**Why the table is in `ui/` and not beside the errors.** `ServiceError` carries
no status by design — `NotFound` is a statement about the domain, and that it
becomes 404 over HTTP is a transport decision. A CLI would map the same codes to
exit statuses; a future mobile backend might not map them at all. A test asserts
no module under `services/` reaches into `ui/`, so the two halves cannot
re-merge.

**Two behaviour changes, both deliberate, both demonstrated.**

*An unclassified exception is now a 500.* The two clauses that inferred a status
from the builtin type are gone. A `KeyError` from a dict-lookup bug used to
answer **404 not found** — which is worse than an honest 500 precisely because
it looks actionable and the user acts on it. Re-adding `except KeyError -> 404`
was the induced failure, and the test catches it.

*A client's unparseable timeframe is a 422, not a 502.* `/api/candles?tf=7m`
answered "candles unavailable" with a 502: H-7 pointing the other way, a typo
dressed as an upstream failure that sends a user to check their internet
connection. The route now re-raises `ServiceError` so the app-wide handler can
give it a 4xx, and catches everything else as the genuine upstream failure it
still is.

**A test that enshrined the defect had to be changed, and it was split.**
`test_unknown_symbol_is_clean_error` asserted the 502. It was also doing two
jobs badly — it fetched an unknown *symbol*, discarded the result, then fetched
a bad *timeframe* and asserted on that. It is now two tests: one that a bad
timeframe is the client's error, one that an unknown symbol is not an error at
all. Changing an assertion that encodes a defect is not weakening a test; the
old one would have failed the moment the defect was fixed, which is what it did.

**Two response shapes, on purpose.** `/api/v1/*` returns the full
`error_envelope` (code, message, details, request id); the legacy routes keep
`{"error": "<message>"}` through one app-wide exception handler, because that is
the shape `index.html` reads and this commit is about statuses, not a frontend
rewrite. Both take their status from the same table.

**`unavailable_provider` is 503, not 502.** The app is reachable and working; an
upstream it depends on is not. A 502 claims *this* server produced an invalid
response, which points a bug report at the wrong system.

**Process note.** The first verification run of this commit was interrupted
mid-flight and left no result. The second failed only on the docs test count —
2390, not the 2387 I had written, because splitting the candles test added one
I had not counted. Both are arguments for re-deriving the count from
`check_docs` output rather than arithmetic.

## C9 — idempotency locks per key, and checks the request

Findings N-1 and N-2. Both only appear under concurrency or a misbehaving
client, which is exactly why neither had a test.

**N-1 — one lock for every key.** `execute` held a single store-wide lock
across the callback. *Spanning the callback* is correct — "execute once per
key" is the whole contract — but *not being per key* was not, so unrelated
mutations serialised: a workspace update waited behind an update check talking
to GitHub. Locks are now per `(operation, key)`, reference-counted, and dropped
at zero so the table is not a memory leak keyed by client input.

The subtle part is the ordering: the reference count is incremented under the
registry lock **before** the per-key lock is acquired. Increment it after, and a
concurrent caller for the same key can find the entry missing, create a second
lock, and both run — which is the single defect the whole method exists to
prevent.

**N-2 — no request fingerprint.** An idempotency key replayed with a *different*
body returned the first request's result and reported success. A client that
reused a key for a different order was told its second order had been placed. It
had not been, and nothing anywhere recorded that. A mismatch now raises
`Conflict`, which C8's table maps to 409.

**An existing test asserted the defect, and this is the second time this
milestone.** `test_v1_idempotency_replays_a_mutation_without_reapplying` sent
`monitoring_only` and then `normal` under one key, and required the second to
come back 200 carrying the first result. It is now two tests: a genuine retry
(same key, same body) replays; a reused key with a different body is a 409 that
leaves the first request's effect untouched. C8 had the same shape with the
502-for-a-bad-timeframe assertion. Both were tests that would fail the moment
their defect was fixed, which is what they did.

**Migration reality.** A row written before C9 has a NULL fingerprint and still
replays. Refusing those would turn an upgrade into a wall of 409s for keys a
client legitimately still holds — both sides must be known before a mismatch can
be claimed. The column is added with `ALTER TABLE ... ADD COLUMN` guarded by
`PRAGMA table_info`, since SQLite has no `ADD COLUMN IF NOT EXISTS`.

**The N-1 test needs threads to see anything at all**, which is the general
lesson repeated from V0.8.2: a test double that models timing but not threads
proves nothing about concurrency. `test_a_slow_mutation_does_not_serialise_a_
different_key` holds one key open in a worker and requires an unrelated key to
complete while it is held; reverting to a single global lock makes it fail with
`['slow', 'quick'] == ['quick']`.

## C10 — a ratchet on the transport's size

`ui/server.py` was 1,892 lines when V0.9.2 opened. It is now **1,629**.
`MAX_UI_SERVER_LINES = 1650` stops it coming back, and the failure message says
what the fix is: move the logic into `services/`, not raise the number.

**The second test is the one that matters.** A ceiling far above the file is not
a constraint, it is a comment. If an extraction leaves more than 120 lines of
slack, `test_the_ceiling_is_still_a_ratchet` fails and names the number to lower
it to. Without it, the first future extraction silently re-grants every line
this milestone won back — the ceiling would still be "passing" at 1,650 with a
900-line file, which is how a gate stops meaning anything without anyone
noticing.

Raising the ceiling to 2,400 was the induced failure, and the ratchet test
catches it and prints "lower MAX_UI_SERVER_LINES to about 1,649".

**A line count is a crude proxy and is worth being honest about.** It cannot
tell a 60-line route table from 60 lines of business logic. What makes it useful
here is not precision but direction: it is a one-way valve on a file whose
regrowth is the specific failure V0.9.2 exists to prevent, and it costs nothing
to run. The real guards are the layering tests above it.

**Incidental fix.** The C4 comment in `test_architecture.py` referenced
`test_services_reach_only_the_order_vocabulary`, a test that does not exist —
the guard shipped as `test_services_never_reach_a_broker_implementation`. A
doc-in-code pointing at a non-existent test is the same drift class the
catalogue checks exist for, so it was corrected rather than left.

## C11 — the application layer, built with no web server

The milestone's central claim, cashed. Every commit since V0.7.0 asserted a
*piece* of it — no `ui` import, no transport package, no HTTP status in a
service. None asserted what a second host actually needs: that you can construct
the registry and **call its services** with no web framework ever loaded.

A subprocess, because the pytest process has imported FastAPI many times over
and an in-process `sys.modules` check would pass regardless. It builds a real
`AppConfig`, `Orchestrator`, `RuntimeSettings`, `BackgroundRuntime` and
`ServiceRegistry`, then calls one method on each of the nine services.
Construction alone proves far less: a registry that builds and raises on first
use is no use to the client this layer exists for.

**It failed on the first run, on a real defect.** Constructing the registry
pulled in `windows_toasts` — a Windows GUI library on the project's own banned
list. `services/` does not import it. It arrived transitively:
`optionspilot/notify/__init__.py` imports `DesktopNotifier`, which imported the
toast package at module scope, and a `NotificationCenter` is injected into the
registry. **No import-graph check over `services/` could ever have seen this**,
which is precisely the gap between "the static ban passes" and "a second host
can actually use this". The import is now lazy, bound on first
`DesktopNotifier()` construction, with the module globals preserved so the
existing desktop tests that monkeypatch them keep working unchanged.

**Then the packaging guard failed on prose.** The lazy import's docstring quotes
`importlib.import_module("windows_toasts")` as the example of what *not* to
write — and `tests/test_packaging.py` scanned source *text* for exactly that
pattern. A comment explaining the rule failed the check enforcing it. The
scanner now walks the AST, and it also had to switch to `utf-8-sig`, because
`data/yfinance_provider.py` carries a BOM that `ast.parse` rejects — a note
`tests/test_architecture.py` already records.

That is the **third** time this milestone a text-matching assertion has broken
on prose about its own rule (C1's `"404"`/`"422"` scan, C5's lock-block search,
this one). The fix is always the same, and it is worth stating as a standing
rule: **match structure, not text.**

**Why the lazy import stays literal.** `from windows_toasts import ...` inside a
function body is still visible to PyInstaller's analysis; `importlib.import_
module("windows_toasts")` is not. Making it a string would have silently dropped
the package from every build — the trap that cost this project yfinance in a
shipped exe, and the reason `tests/test_packaging.py` exists at all.
