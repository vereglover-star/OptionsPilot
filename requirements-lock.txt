# OptionsPilot dependency lock (pip constraints format).
#
# WHY THIS FILE EXISTS
# pyproject.toml declares floors only ("pandas>=2.2"), so an unconstrained
# install resolves whatever is newest that day. A release built on Monday and
# the "same" release rebuilt on Friday could ship different libraries. This
# file pins the exact set that the test suite was last verified green against,
# so a build is reproducible and an upstream release cannot ship itself to
# users through a tag push.
#
# HOW IT IS APPLIED
# As a pip *constraints* file, never as a requirements file:
#     pip install -e ".[dev,ui]" -c requirements-lock.txt
# pyproject.toml stays the source of truth for WHICH packages are needed;
# this file only decides WHICH VERSION of them is installed. A pin for a
# package nobody requests is inert, which is what keeps one lock correct on
# both Windows and Linux: the Windows-only entries below (pythonnet, pystray,
# pywin32-ctypes, clr_loader, ...) simply never install on a Linux runner.
#
# WHY CONSTRAINTS AND NOT A HASH-PINNED LOCKFILE
# `pip install -e .` is incompatible with `--require-hashes`, and every
# workflow in this repo (dev, CI, release, the PyInstaller build) is built on
# an editable install. A hash-pinned lock would mean giving that up. Known
# limitation, stated plainly: a NEW transitive dependency that appears in a
# future upstream release is not listed here and would float until this file
# is regenerated. Constraints bound the versions of what is already known,
# not the shape of the dependency graph.
#
# HOW TO REGENERATE
# Only from an environment whose full test suite is green — this file is a
# record of a verified state, not a wish:
#     .venv\Scripts\python -m pytest          # must pass first
#     .venv\Scripts\python -m pip freeze --exclude-editable
# Sort the result and replace the block below. `--exclude-editable` matters:
# without it pip emits the project itself as a VCS URL and the lock becomes
# self-referential. tests/test_release_tooling.py::TestDependencyLock checks
# that this file and pyproject.toml never disagree about a direct dependency.
#
# Verified green: 2079 tests, Python 3.12, Windows.
